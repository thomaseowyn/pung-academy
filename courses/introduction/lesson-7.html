Collections

    Learning material

    Why collections exist

    Storing one student's grade is easy. Storing thirty is not — at least not the way you know so far: 

    grade_1 = 78
grade_2 = 91
grade_3 = 65
# ... twenty-seven more lines

    This is unworkable. You cannot loop over those variables, you cannot count them, and adding a student means editing the program. A collection holds many values under one name.

    Lists

    A list is an ordered collection. Square brackets, commas between items: 

    grades = [78, 91, 65, 84, 72]
names = ["Alex", "Bo", "Chris"]
mixed = ["Alex", 20, True]     # allowed, though rarely a good idea

    len() tells you how many items a list holds: 

    print(len(grades))    # 5

    Accessing list elements

    Each item has a position, called its index. Indexes start at 0, not 1. 

    names = ["Alex", "Bo", "Chris"]

print(names[0])    # Alex
print(names[1])    # Bo
print(names[2])    # Chris

    Counting from zero feels wrong for about a week and then becomes invisible. The consequence worth memorising: the last item of a list of length 5 is at index 4. 

    print(names[-1])   # Chris  -- negative counts back from the end
print(names[-2])   # Bo
    Careful

    Asking for an index that does not exist crashes with IndexError: list index out of range. With three items, names[3] is already past the end.

    Modifying lists

    Unlike strings, lists can be changed after they are created.

    tasks = ["Wash up", "Email tutor"]

tasks.append("Buy milk")        # add to the end
print(tasks)                    # ['Wash up', 'Email tutor', 'Buy milk']

tasks[0] = "Wash the dishes"    # replace by index
print(tasks)                    # ['Wash the dishes', 'Email tutor', 'Buy milk']

tasks.remove("Email tutor")     # remove by value
print(tasks)                    # ['Wash the dishes', 'Buy milk']

del tasks[0]                    # remove by index
print(tasks)                    # ['Buy milk']

    append() is a method — a function that belongs to an object and is called with a dot. You will use append() more than any other list method, because building a list up item by item is such a common shape.

    Looping through lists

    This is where lists and Chapter 6 meet, and it is the payoff for both. 

    grades = [78, 91, 65, 84, 72]

for grade in grades:
    print(grade)

    No range() and no indexes needed. The loop variable takes each value in turn. This works identically whether the list has three items or three thousand.

    The accumulator pattern, again

    grades = [78, 91, 65, 84, 72]
total = 0

for grade in grades:
    total += grade

average = total / len(grades)
print(f"Average: {average}")
    Output 
    Average: 78.0

    The running-best pattern

    Finding the largest value uses a variable that keeps the best answer found so far: 

    grades = [78, 91, 65, 84, 72]
highest = grades[0]

for grade in grades:
    if grade > highest:
        highest = grade

print(f"Highest: {highest}")     # 91

    Start by assuming the first item wins, then replace it whenever something better appears. Writing this by hand once is worth more than knowing that max() exists — and it does exist, for when you are not practising.

    When you need the position too

    names = ["Alex", "Bo", "Chris"]

for position, name in enumerate(names, start=1):
    print(f"{position}. {name}")
    Output 
    1. Alex
2. Bo
3. Chris

    Dictionaries

    A list is indexed by position, which is fine when order is what matters. Often it is not — you want to look something up by name.

    A dictionary stores key-value pairs. Curly braces, and each entry is key: value: 

    student = {
    "name": "Alex",
    "age": 20,
    "grade": 78
}

    You look values up by key rather than by position:

    print(student["name"])    # Alex
print(student["grade"])   # 78

    Compare that with student[0] on a list, where you have to remember that position 0 was the name. Dictionaries say what they mean.

    Changing and adding

    student["grade"] = 85          # change an existing value
student["city"] = "Jakarta"    # a new key simply appears
del student["age"]             # remove a pair

print(student)
    Output 
    {'name': 'Alex', 'grade': 85, 'city': 'Jakarta'}
    Careful

    Asking for a key that does not exist raises KeyError. To look up safely, use student.get("city"), which returns None instead of crashing when the key is missing.

    Looping through a dictionary

    student = {"name": "Alex", "grade": 78}

for key in student:
    print(key, "->", student[key])

for key, value in student.items():
    print(f"{key}: {value}")

    Lists of dictionaries

    These two combine into the shape you will use for almost every real collection of records: 

    students = [
    {"name": "Alex", "grade": 78},
    {"name": "Bo", "grade": 91},
    {"name": "Chris", "grade": 65}
]

for student in students:
    print(f"{student['name']}: {student['grade']}")
    Output 
    Alex: 78
Bo: 91
Chris: 65
    Tip — which one to use

    Ask how you will look things up. Going through everything in order, or caring about position? Use a list. Fetching one thing by a name or id? Use a dictionary. A collection of records? A list of dictionaries.

    Worked example — the Student Grade Manager

    # Student Grade Manager

students = [
    {"name": "Alex", "grade": 78},
    {"name": "Bo", "grade": 91},
    {"name": "Chris", "grade": 65},
    {"name": "Dev", "grade": 84}
]

total = 0
best = students[0]

for student in students:
    total += student["grade"]
    if student["grade"] > best["grade"]:
        best = student

average = total / len(students)

print("--- Class report ---")
for student in students:
    status = "pass" if student["grade"] >= 70 else "fail"
    print(f"{student['name']:<6} {student['grade']:>3}  {status}")

print()
print(f"Students: {len(students)}")
print(f"Average:  {average}")
print(f"Top:      {best['name']} with {best['grade']}")
    Output 
    --- Class report ---
Alex    78  pass
Bo      91  pass
Chris   65  fail
Dev     84  pass

Students: 4
Average:  79.5
Top:      Bo with 91

    One loop does two jobs at once — accumulating the total and tracking the best — and a second loop prints the report. Both patterns are from earlier in this chapter, now working on real records.
