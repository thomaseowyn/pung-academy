    Learning material

    Why functions?

    Look at a program that greets three people: 

    print("Hello, Alex!")
print("Welcome to Pung Academy.")

print("Hello, Bo!")
print("Welcome to Pung Academy.")

print("Hello, Chris!")
print("Welcome to Pung Academy.")

    The same idea, written three times. Change the welcome message and you must change it in three places — and eventually you will change two of them and ship the third.

    A function is a named piece of work you define once and use as often as you like. You have been calling functions since Chapter 2: print(), input(), len(), int(). Now you write your own.

    Creating functions

    def greet():
    print("Hello!")
    print("Welcome to Pung Academy.")

    The parts:

    • def tells Python you are defining a function.
    • greet is the name. Same rules as variable names, and it should describe an action.
    • The brackets will hold inputs — empty for now.
    • The colon and indented body, exactly as with if and for.

    Defining a function does not run it. It only teaches Python what the name means. To run it, call it: 

    def greet():
    print("Hello!")

greet()
greet()
    Output 
    Hello!
Hello!
    Careful

    greet without brackets does not call the function — it just refers to it. The brackets are what say "do it now".

    Parameters and arguments

    A function that always does exactly the same thing is limited. A parameter is a name inside the brackets that stands for a value the caller will supply. 

    def greet(name):
    print(f"Hello, {name}!")

greet("Alex")
greet("Bo")
    Output 
    Hello, Alex!
Hello, Bo!

    The two words are often used loosely, but they are different things:

    • Parameter — the name in the definition (name). A placeholder.
    • Argument — the actual value passed in when calling ("Alex").

    Several parameters

    def describe(name, age, city):
    print(f"{name} is {age} and lives in {city}.")

describe("Alex", 20, "Jakarta")

    Order matters — arguments are matched to parameters by position. Calling describe(20, "Alex", "Jakarta") produces nonsense without any error at all.

    Default values

    def greet(name, greeting="Hello"):
    print(f"{greeting}, {name}!")

greet("Alex")                      # Hello, Alex!
greet("Bo", "Good morning")        # Good morning, Bo!

    Return values

    This is the idea that makes functions powerful, and the one beginners most often miss. So far our functions have printed things. Printing shows a human some text. It does not give the value back to the program.

    return hands a value back to whoever called the function: 

    def add(a, b):
    return a + b

result = add(2, 3)
print(result)          # 5
print(add(10, 20))     # 30
print(add(1, 2) * 10)  # 30

    Compare the two versions carefully:

    def add_and_print(a, b):
    print(a + b)          # shows the answer, gives back nothing

def add_and_return(a, b):
    return a + b          # hands the answer back

x = add_and_print(2, 3)   # prints 5, but x is None
y = add_and_return(2, 3)  # prints nothing, but y is 5
    Tip

    A function that calculates something should nearly always return the result rather than print it. Printing is a decision about presentation — leave it to the code that called you, which knows what it wants to do with the answer.

    return ends the function immediately

    def check_age(age):
    if age < 0:
        return "That is not a valid age."
    if age >= 18:
        return "Adult"
    return "Minor"

print(check_age(20))    # Adult
print(check_age(-5))    # That is not a valid age.

    Nothing after a return that runs will execute. That makes it useful for handling bad input at the top and getting out early.

    Breaking problems into functions

    Decomposition is splitting a large problem into small named pieces. It is the single most valuable habit in this chapter.

    Consider a quiz. As one block it is a tangle. Divided up, each piece is small enough to hold in your head and test on its own: 

    def ask_question(question, correct_answer):
    """Ask one question. Return True if answered correctly."""
    given = input(question + " ")
    return given.strip().lower() == correct_answer.lower()


def report(score, total):
    """Print the final result."""
    print(f"You scored {score} out of {total}.")
    if score == total:
        print("Perfect.")
    elif score >= total / 2:
        print("A decent effort.")
    else:
        print("Worth another go.")

    The text in triple quotes at the top of each function is a docstring — a short note about what the function does, for anyone reading it later.

    Signs a function is doing too much

    • You struggle to name it without using "and".
    • It is longer than about twenty lines.
    • You cannot describe what it returns in one sentence.

    Worked example — the Quiz Game

    # Quiz Game

def ask_question(question, correct_answer):
    given = input(question + " ")
    return given.strip().lower() == correct_answer.lower()


def report(score, total):
    print()
    print(f"You scored {score} out of {total}.")
    if score == total:
        print("Perfect.")
    elif score >= total / 2:
        print("A decent effort.")
    else:
        print("Worth another go.")


questions = [
    {"q": "What does CPU stand for?", "a": "central processing unit"},
    {"q": "What symbol starts a comment in Python?", "a": "#"},
    {"q": "What is 7 * 6?", "a": "42"}
]

score = 0

for item in questions:
    if ask_question(item["q"], item["a"]):
        print("Correct.")
        score += 1
    else:
        print(f"No - the answer was {item['a']}.")

report(score, len(questions))
    Output 
    What does CPU stand for? central processing unit
Correct.
What symbol starts a comment in Python? #
Correct.
What is 7 * 6? 41
No - the answer was 42.

You scored 2 out of 3.
A decent effort.

    Every idea from the course so far is in there: variables, a list of dictionaries, a loop, conditions, and two functions that each do one job. .strip().lower() makes the check forgiving of stray spaces and capitals — a small kindness worth building into anything that reads human input.

    Small exercise

    What does this print, and why is it not 8?

    def double(number):
    number * 2

print(double(4))

    It prints None. The function calculates the double and then throws it away — there is no return.
