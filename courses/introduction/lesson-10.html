    Learning material

    The final project

    Nine chapters of pieces. Now you build something whole: a Personal Task Manager that runs at the command line and keeps track of things you have to do.

    There is no new syntax in this chapter. Everything you need you already have. What is new is the size — this is the first program where you have to hold several parts in your head at once, and that is exactly the skill being practised.

    What it must do

    The program shows a menu, and keeps showing it until the user exits:

    1. Add task — ask for a description and store it
    2. View tasks — list them all, numbered, showing which are done
    3. Complete task — mark one as finished
    4. Delete task — remove one entirely
    5. Search task — find tasks whose text contains a word
    6. Count completed — report how many are done
    7. Exit — stop the program

    Planning before coding

    Chapter 1 said to plan before typing, and this is where that pays off. Two decisions come first.

    How will you store a task?

    A task has a description and a done/not-done state. A plain string cannot carry both, so use a dictionary per task, and a list to hold them all: 

    tasks = [
    {"title": "Buy milk", "done": False},
    {"title": "Email tutor", "done": True}
]

    What is the shape of the program?

    CREATE an empty list of tasks

REPEAT forever
    SHOW the menu
    ASK for a choice

    IF choice is 1, add a task
    IF choice is 2, view tasks
    ...
    IF choice is 7, STOP repeating
    OTHERWISE say the choice was not understood

    That is a while True: loop with an if/elif chain inside and a break on exit — Chapters 5 and 6 together.

    Building it piece by piece

    The menu loop

    Start with the skeleton and check it runs before adding anything:

    tasks = []

while True:
    print()
    print("--- Task Manager ---")
    print("1. Add task")
    print("2. View tasks")
    print("3. Complete task")
    print("4. Delete task")
    print("5. Search tasks")
    print("6. Count completed")
    print("7. Exit")

    choice = input("Choose an option: ")

    if choice == "7":
        print("Goodbye.")
        break
    else:
        print("Not implemented yet.")
    Tip

    Compare with "7" in quotes. input() gives text, so comparing against the number 7 would never match — the bug from Chapter 3, waiting patiently.

    Adding a task

    def add_task():
    title = input("What needs doing? ")
    tasks.append({"title": title, "done": False})
    print(f"Added: {title}")

    Viewing tasks

    def view_tasks():
    if len(tasks) == 0:
        print("You have no tasks.")
        return

    for number, task in enumerate(tasks, start=1):
        mark = "x" if task["done"] else " "
        print(f"{number}. [{mark}] {task['title']}")

    The early return handles the empty case first, so the rest of the function can assume there is something to show.

    Completing and deleting

    Both ask which task, and both must cope with a number that does not exist: 

    def complete_task():
    view_tasks()
    if len(tasks) == 0:
        return

    number = int(input("Which number is done? "))
    if 1 <= number <= len(tasks):
        tasks[number - 1]["done"] = True
        print("Marked as complete.")
    else:
        print("There is no task with that number.")
    Careful — the off-by-one

    You show tasks numbered from 1 because that is what humans expect, but the list is indexed from 0. Hence tasks[number - 1]. Forget the - 1 and you will complete the wrong task every time.

    Searching and counting

    def search_tasks():
    term = input("Search for: ").lower()
    found = 0

    for task in tasks:
        if term in task["title"].lower():
            print("-", task["title"])
            found += 1

    if found == 0:
        print("Nothing matched.")


def count_completed():
    done = 0
    for task in tasks:
        if task["done"]:
            done += 1

    print(f"{done} of {len(tasks)} tasks completed.")

    in checks whether one string appears inside another, and .lower() on both sides makes the search ignore capitals — the same kindness as the quiz in Chapter 8.

    Wiring it together

        if choice == "1":
        add_task()
    elif choice == "2":
        view_tasks()
    elif choice == "3":
        complete_task()
    elif choice == "4":
        delete_task()
    elif choice == "5":
        search_tasks()
    elif choice == "6":
        count_completed()
    elif choice == "7":
        print("Goodbye.")
        break
    else:
        print("Please choose a number from 1 to 7.")

    Each branch is one line calling one function. That readability is the whole argument for decomposition.

    Testing your project

    Before calling it finished, deliberately try to break it:

    • View tasks when there are none.
    • Complete task number 99.
    • Delete the only task, then view.
    • Search for something that does not exist.
    • Choose option 9, or type a letter.
    • Add a task with an empty description.

    Every one of those is a real thing a user will do within a minute of opening your program.

    Optional challenges

    Finish the core seven options first. Then, if you want to push further:

    • Priority — add a "priority" key of high, medium or low, and show it in the list.
    • Categories — tag tasks as work, study or personal, and let the user view one category.
    • Due dates — store a date string and mark anything overdue.
    • Sorting — show unfinished tasks before finished ones.
    Note

    Your tasks disappear when the program stops, because they only live in memory. Saving them to a file is the natural next thing to learn — and it is where the courses after this one pick up.

    Before you submit

    The check below looks for the structural pieces the project needs: at least one function, a repeating menu loop, input, a branch on the choice, a collection holding the tasks, and a way out of the loop. Write the real thing — you are the person who loses if you write only enough to pass a pattern check.
