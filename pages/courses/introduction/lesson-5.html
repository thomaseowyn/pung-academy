    Learning material

    Why programs need decisions

    Every program you have written so far does exactly the same thing every time it runs. Useful programs do not. They react: a login page behaves differently for the right password than the wrong one; a game reacts differently to a hit than to a miss.

    A conditional statement lets a program choose between paths, based on a boolean. This is where the comparison operators from Chapter 4 start earning their keep.

    The if statement

    age = 20

if age >= 18:
    print("You are an adult.")
    Output 
    You are an adult.

    The anatomy of that, piece by piece:

    • if starts the statement.
    • age >= 18 is the condition. It produces True or False.
    • The colon at the end of the line is required. Forgetting it is a rite of passage.
    • The indented line underneath is the body — the code that runs only if the condition is True.

    Indentation is the block

    In Python, indentation is not decoration. It is how the language knows which lines belong to the if. Compare: 

    age = 10

if age >= 18:
    print("You are an adult.")
    print("This line is indented, so it only runs for adults.")
print("This line is not indented, so it always runs.")
    Output 
    This line is not indented, so it always runs.
    Careful

    Use four spaces per level and be consistent. Mixing tabs and spaces produces IndentationError or, worse, code that runs but groups the wrong lines together.

    else: the other path

    else supplies what happens when the condition is False. It has no condition of its own — it is simply "otherwise". 

    age = 15

if age >= 18:
    print("You are an adult.")
else:
    print("You are not an adult yet.")
    Output 
    You are not an adult yet.

    With if/else, exactly one of the two branches runs. Never both, never neither.

    elif: more than two options

    elif — short for "else if" — adds extra conditions, each tested only if the ones above it were False. 

    score = 74

if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
elif score >= 70:
    grade = "C"
elif score >= 60:
    grade = "D"
else:
    grade = "F"

print(f"Your grade is {grade}")
    Output 
    Your grade is C

    Python checks top to bottom and stops at the first match. With a score of 74 it asks "90 or more?" (no), "80 or more?" (no), "70 or more?" (yes) — and then skips everything below without testing it.

    Careful — order matters enormously

    Write that same chain starting with score >= 60 and every passing score becomes a D, because the first branch catches them all. With overlapping ranges, always test the narrowest or highest condition first.

    Nested conditions

    An if can live inside another if. The inner one is only reached when the outer condition passed. 

    logged_in = True
is_admin = False

if logged_in:
    print("Welcome back!")
    if is_admin:
        print("You have admin access.")
    else:
        print("You have standard access.")
else:
    print("Please log in.")
    Output 
    Welcome back!
You have standard access.

    Note if logged_in: with no comparison at all. The variable is already a boolean, so comparing it to True would be redundant.

    Tip

    Deep nesting gets unreadable fast. If you find yourself four levels in, that is usually a sign the conditions should be combined with and, or the work moved into a function — which you will learn in Chapter 8.

    Combining conditions

    Rather than nesting, join conditions with the logical operators from Chapter 4: 

    age = 20
has_ticket = True

if age >= 18 and has_ticket:
    print("Enjoy the film.")
elif age >= 18 and not has_ticket:
    print("You need to buy a ticket.")
else:
    print("You are too young for this film.")

    These two are identical in behaviour — pick whichever reads better:

    # nested
if logged_in:
    if is_admin:
        print("Admin panel")

# combined
if logged_in and is_admin:
    print("Admin panel")

    Worked example — the Grade Calculator

    This chapter's project, with the input validation the calculator in Chapter 4 was missing. 

    # Grade Calculator

name = input("Student name: ")
score = float(input("Score out of 100: "))

if score < 0 or score > 100:
    print("That is not a valid score.")
else:
    if score >= 90:
        grade = "A"
    elif score >= 80:
        grade = "B"
    elif score >= 70:
        grade = "C"
    elif score >= 60:
        grade = "D"
    else:
        grade = "F"

    print(f"{name} scored {score} and receives grade {grade}.")

    if grade == "F":
        print("This is a fail. Please see your tutor.")
    elif grade == "A":
        print("Outstanding work.")
    Output 
    Student name: Alex
Score out of 100: 93

Alex scored 93.0 and receives grade A.
Outstanding work.

    The invalid-input check comes first and everything else sits in its else. Rejecting bad data before working with it is a habit worth forming now — most real bugs come from data that was not what the programmer assumed.

    Small exercise

    What does this print, and why is it probably not what the author intended? 

    temperature = 35

if temperature > 0:
    print("Above freezing")
elif temperature > 30:
    print("Very hot")

    It prints only "Above freezing". The first condition is true, so Python never tests the second. The branches are in the wrong order.
