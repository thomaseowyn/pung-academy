    Learning material

    Programs that remember

    Every program you have written so far forgets everything the moment it closes. The task list from an earlier chapter's exercise vanished the instant the program ended. To keep data between runs, a program has to save it somewhere outside its own memory — usually a file.

    Opening a file with with

    with open("notes.txt", "w") as file:
    file.write("Remember to practise loops.\n")

    open() takes a filename and a mode. with hands you the open file as file, and — this is the important part — closes it automatically once the indented block finishes, even if something inside it goes wrong. That is why with is the standard way to work with files rather than calling open() and close() separately.

    File modes

    • "w" — write. Creates the file if needed, and erases whatever was already in it.
    • "a" — append. Adds to the end without erasing what is already there.
    • "r" — read. Opens an existing file to look at its contents.
    Careful — the mode trap

    Opening a file you meant to add to with "w" wipes it silently, with no warning. If you are not sure whether a file should be replaced or added to, that is the question to ask before you open it.

    Reading a file back

    with open("notes.txt", "r") as file:
    contents = file.read()

print(contents)

    You can also read a file one line at a time, which is usually more useful once a file has more than a few lines: 

    with open("notes.txt", "r") as file:
    for line in file:
        print(line.strip())

    .strip() removes the newline character that comes along with each line — without it, every printed line would have an extra blank line after it.

    Working with CSV

    CSV — comma-separated values — is a plain text format for tabular data, one row per line, values separated by commas. You can read a CSV file as plain text and split each line yourself: 

    with open("scores.csv", "r") as file:
    for line in file:
        name, score = line.strip().split(",")
        print(f"{name}: {score}")

    .split(",") breaks a line into a list wherever a comma appears — one string in, several strings out.

    Working with JSON

    JSON stores structured data — dictionaries and lists — as text, and it is the format you will see most often once you start working with real APIs. Python's built-in json module converts between the two directly: 

    import json

data = {"name": "Alex", "scores": [78, 91, 65]}

text = json.dumps(data)
print(text)          # '{"name": "Alex", "scores": [78, 91, 65]}'

parsed = json.loads(text)
print(parsed["name"])   # Alex

    json.dumps() turns a Python dictionary into a JSON string. json.loads() does the reverse, and json.dump() / json.load() (without the s) do the same thing directly to and from an open file. 

    import json

with open("student.json", "w") as file:
    json.dump({"name": "Alex", "grade": 78}, file)
    Tip — tracing a JSON parse

    If json.loads() fails, the error usually names the exact character position where the text stopped looking like valid JSON — a missing comma or an unclosed brace is the most common cause.

    Worked example — a Persistent Notes App

    This chapter's project saves notes to a file so they survive between runs of the program — the first project in this course that actually remembers anything after it closes. 

    # Persistent Notes App

print("--- Your saved notes ---")

try:
    with open("my_notes.txt", "r") as file:
        for line in file:
            print("-", line.strip())
except FileNotFoundError:
    print("(no notes saved yet)")

new_note = input("\nAdd a note (or press Enter to skip): ")

if new_note:
    with open("my_notes.txt", "a") as file:
        file.write(new_note + "\n")
    print("Saved.")

    Reading happens first, wrapped in a try/except FileNotFoundError so the very first run — before the file exists at all — does not crash. Writing uses "a" rather than "w" deliberately, so each new note is added rather than erasing everything saved before it.

    Small exercise

    If you open a file twice in a row with mode "w" and write different text each time, what ends up in the file? Only the second write — "w" erases the file's previous contents every single time it is opened.
