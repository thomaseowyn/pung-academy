    Learning material

    Writing it the Python way

    Everything in this chapter does something you can already do with a loop and an if statement. What is new is writing it in the shorter, more direct style experienced Python programmers reach for by default — usually called Pythonic code.

    List comprehensions

    Compare these two, which do exactly the same thing:

    # The loop version
squares = []
for number in range(1, 6):
    squares.append(number ** 2)

# The comprehension version
squares = [number ** 2 for number in range(1, 6)]

print(squares)   # [1, 4, 9, 16, 25]

    A list comprehension builds a new list in one expression: [expression for item in sequence]. You can add a filter with if at the end: 

    numbers = [1, 2, 3, 4, 5, 6, 7, 8]
evens = [number for number in numbers if number % 2 == 0]
print(evens)   # [2, 4, 6, 8]
    Tip — translating a comprehension

    Read [x for x in numbers if x % 2 == 0] aloud as "x, for every x in numbers, but only where x is even" — reading it in that order, left to right, is what makes comprehensions click.

    Lambda functions

    A lambda is a small, unnamed function written in a single line — useful when you need a tiny function just once, somewhere a full def would feel heavy. 

    square = lambda x: x ** 2
print(square(5))   # 25

# equivalent to:
def square(x):
    return x ** 2

    A lambda can only contain one expression, and it always returns that expression's value — there is no return keyword because none is needed.

    map() and filter()

    map() applies a function to every item in a sequence; filter() keeps only the items a function says yes to. Both are often paired with a lambda: 

    numbers = [1, 2, 3, 4, 5]

doubled = list(map(lambda x: x * 2, numbers))
print(doubled)   # [2, 4, 6, 8, 10]

evens = list(filter(lambda x: x % 2 == 0, numbers))
print(evens)     # [2, 4]

    Both return a special lazy object rather than a list directly, which is why they are wrapped in list(...) to see the result. A list comprehension does the same job and most Python programmers reach for it first — map and filter are worth recognising when you meet them in other people's code.

    Generators, briefly

    A generator produces values one at a time, on demand, instead of building a whole list in memory at once. The simplest way to make one looks almost like a list comprehension, but with round brackets: 

    squares = (number ** 2 for number in range(1, 1000000))

    That line runs instantly, because no squares have actually been calculated yet — they are produced one at a time only as something asks for the next one. This matters once you are working with data too large to hold in memory all at once; for now, just recognise the shape when you see it.

    @staticmethod, briefly

    A static method lives inside a class but does not need self, because it does not touch any particular object's data — it is just related, logically, to the class. 

    class MathHelper:
    @staticmethod
    def add(a, b):
        return a + b


print(MathHelper.add(2, 3))   # 5 -- called on the class, no object needed

    The final project

    This is where every chapter of this course meets in one place. You are going to rebuild the classic task manager idea, but properly this time — as a class, the way Chapter 12 taught, instead of loose dictionaries.

    The shape you are building towards:

    Plan a Task class
├── __init__(self, title)   -> store the title, start as not done
├── complete(self)          -> mark it done
└── __str__(self)           -> a readable "[x] Buy milk" line

Then the program
├── an empty list to hold Task objects
├── a while loop that shows a menu and reads a choice
├── add    -> create a Task and append it
├── view   -> loop through the list and print each one
├── complete -> show the list, ask which number, call .complete()
└── exit   -> break out of the loop

    Nothing in that tree is new. It is every earlier chapter, assembled: a class (11), a list of objects (5), a menu loop with input() and branching (3, 4, 7), and enumerate() for numbering the list on screen (6).
