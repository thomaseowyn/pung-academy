    Learning material

    You do not have to write everything yourself

    Python ships with a large standard library of ready-made code, and beyond that, an enormous ecosystem of packages other people have published. Using them is normal practice, not cheating — this chapter is about how to bring that code into your own program.

    Importing built-in modules

    import random

roll = random.randint(1, 6)
print(roll)

    import random gives your file access to everything inside the random module. You already used this back in the loops chapter's worked example — a die roll picks a whole number in a range, which is exactly what random.randint(1, 6) does.

    Two more modules you will meet constantly:

    import math
print(math.sqrt(16))     # 4.0
print(math.pi)            # 3.141592653589793

import datetime
today = datetime.date.today()
print(today)               # e.g. 2026-09-08

    Importing just one piece

    You can import a single name from a module instead of the whole thing, which saves you writing the module name every time: 

    from random import randint

roll = randint(1, 6)   # no "random." needed now
    Careful — namespace collisions

    If you write from random import * to import everything at once, and one of those names happens to match a variable or function you already defined, yours gets silently overwritten. Import only what you need, by name, and prefer import module_name when in doubt — it is clearer where each piece came from.

    Third-party packages and pip

    The standard library covers a lot, but not everything. pip is Python's package installer, and it downloads code other people have published so you can import it just like a built-in module. 

    pip install requests

    That command is typed into your terminal, not into a Python file. Once installed, a package behaves exactly like a built-in module — import requests and you can use it.

    Virtual environments (venv)

    Different projects on your computer can need different versions of the same package. A virtual environment is an isolated Python installation for a single project, so installing something for one project can never break another. 

    python -m venv env
# then activate it — the exact command differs by operating system
# Windows:      env\Scripts\activate
# macOS/Linux:  source env/bin/activate

    Once activated, anything you pip install is contained inside that project's own env folder, completely separate from every other project on your machine. This is standard practice the moment a project depends on anything beyond the standard library.

    Tip — import path resolution

    Python looks for a module first among the files in your own project, then in the active virtual environment, then in the standard library. If import ever picks up the wrong version of something, checking which environment is active is usually the fastest way to find out why.

    Worked example — the Daily Dice Roller

    This chapter's project combines two built-in modules — one to generate something random, one to timestamp it. 

    # Daily Dice Roller

import random
import datetime

facts = [
    "Python was named after Monty Python, not the snake.",
    "The zen of Python can be read by typing: import this",
    "f-strings were added in Python 3.6."
]

roll = random.randint(1, 6)
fact = random.choice(facts)
today = datetime.date.today()

print(f"[{today}] You rolled a {roll}.")
print(f"Fact of the day: {fact}")
    Output 
    [2026-09-08] You rolled a 4.
Fact of the day: f-strings were added in Python 3.6.

    random.choice() picks one item at random from a list — useful the moment you have several options and want one of them, rather than a number.

    Small exercise

    What is the difference between import random and from random import randint? The first requires writing random.randint(...) every time; the second lets you write randint(...) directly, because only that one name was brought in.
