    Learning material

    Programs fail. Plan for it.

    Every program you have written so far breaks the instant something unexpected happens — a letter typed where a number was expected, a file that is not there, a list that turns out to be empty. Error handling is how you let a program expect that, and keep running anyway.

    try and except

    try:
    number = int(input("Enter a number: "))
    print(f"You entered {number}")
except ValueError:
    print("That was not a valid number.")
    Output (typing "abc") 
    Enter a number: abc
That was not a valid number.

    Python attempts everything inside try. The moment a line raises an error matching the type named after except, it jumps straight there instead of crashing the whole program.

    Catching more than one kind of error

    try:
    first = int(input("First number: "))
    second = int(input("Second number: "))
    print(first / second)
except ValueError:
    print("Please type actual numbers.")
except ZeroDivisionError:
    print("You cannot divide by zero.")

    Two separate except blocks, each matching a different failure — Python checks them in order and runs whichever one matches. You can also catch several types in one block with a tuple: except (ValueError, ZeroDivisionError):.

    else and finally

    try:
    number = int(input("Enter a number: "))
except ValueError:
    print("That was not valid.")
else:
    print(f"Got it: {number}")
finally:
    print("Done trying.")
    • else runs only if try succeeded with no error at all.
    • finally always runs, whether there was an error or not — useful for cleanup that must happen either way.

    Raising your own exceptions

    Sometimes the input is technically valid Python but wrong for what your program needs — a negative age, for instance. You can raise an error on purpose: 

    age = int(input("Age: "))

if age < 0:
    raise ValueError("Age cannot be negative")

print(f"Age accepted: {age}")

    raise stops the program immediately with your chosen error — unless something further up the call chain catches it with its own try/except.

    Reading a stack trace

    When an error is not caught, Python prints a stack trace — read the bottom line first. 

    Traceback (most recent call last):
  File "shopping.py", line 7, in <module>
    total = price * quantity
TypeError: can't multiply sequence by non-int of type 'str'

    Working from the bottom up:

    • Last line — the error family (TypeError) and the exact complaint.
    • File and line number — where to look.
    • The quoted code — the exact line that failed.

    Translated: something tried to multiply a piece of text by a value that was not a plain integer. Almost certainly quantity came from input() and was never converted with int().

    Tip — exception matching

    When you have several except blocks, Python checks them top to bottom and stops at the first type that matches. Order the specific ones before any general catch-all, or the specific ones will never be reached.

    Worked example — the Safe Calculator

    This chapter's project takes the division calculator from earlier and makes it resilient — no input can crash it. 

    # Safe Calculator

while True:
    try:
        first = float(input("First number (or 'q' to quit): "))
        second = float(input("Second number: "))
    except ValueError:
        print("Please enter valid numbers.\n")
        continue

    try:
        result = first / second
    except ZeroDivisionError:
        print("Cannot divide by zero.\n")
        continue

    print(f"Result: {result}\n")
    break
    Output (dividing by zero, then succeeding) 
    First number (or 'q' to quit): 10
Second number: 0
Cannot divide by zero.

First number (or 'q' to quit): 10
Second number: 2
Result: 5.0

    Two separate try blocks handle two separate failures, and continue sends the loop straight back to asking again rather than letting a bad attempt end the program.

    Small exercise

    Which except block catches this error, and why? 

    try:
    numbers = [1, 2, 3]
    print(numbers[10])
except ValueError:
    print("A")
except IndexError:
    print("B")

    "B" — asking a list for an index that does not exist raises IndexError, not ValueError.
