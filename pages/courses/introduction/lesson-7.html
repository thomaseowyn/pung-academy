    Learning material

    Why functions?

    Look at a program that greets three people: 

    print("Hello, Alex!")
print("Welcome to Pung Academy.")

print("Hello, Bo!")
print("Welcome to Pung Academy.")

    The same idea, written twice already, and it will only get worse. A function is a named piece of work you define once and use as often as you like. You have already been calling functions: print(), input(), len(). Now you write your own.

    Defining and calling a function

    def greet():
    print("Hello!")
    print("Welcome to Pung Academy.")

greet()
greet()
    Output 
    Hello!
Welcome to Pung Academy.
Hello!
Welcome to Pung Academy.

    Defining a function does not run it — it only teaches Python what the name means. Writing greet() with brackets is what actually runs it.

    Parameters and arguments

    A parameter is a placeholder name in the definition; an argument is the actual value you pass in when calling. 

    def greet(name):
    print(f"Hello, {name}!")

greet("Alex")
greet("Bo")
    Output 
    Hello, Alex!
Hello, Bo!

    Default arguments

    def greet(name, greeting="Hello"):
    print(f"{greeting}, {name}!")

greet("Alex")                      # Hello, Alex!
greet("Bo", "Good morning")        # Good morning, Bo!

    *args and **kwargs

    Sometimes you do not know in advance how many arguments a function should accept. *args collects any number of extra positional arguments into a tuple: 

    def total(*args):
    return sum(args)

print(total(1, 2, 3))       # 6
print(total(10, 20))        # 30

    **kwargs does the same for named arguments, collecting them into a dictionary: 

    def describe(**kwargs):
    for key, value in kwargs.items():
        print(f"{key}: {value}")

describe(name="Alex", age=20)
    Output 
    name: Alex
age: 20

    You will not need these two constantly as a beginner, but recognising them is important — they appear throughout Python's own libraries.

    return vs. print

    This is the idea that makes functions powerful, and the one beginners most often miss. print() shows a human some text — it does not give a value back to the rest of the program. return does. 

    def add_and_print(a, b):
    print(a + b)          # shows the answer, gives back nothing

def add_and_return(a, b):
    return a + b          # hands the answer back

x = add_and_print(2, 3)   # prints 5, but x is None
y = add_and_return(2, 3)  # prints nothing, but y is 5
    Tip

    A function that calculates something should almost always return the result rather than print it — printing is a decision about presentation, and it is not the function's job to make that call for whoever uses it.

    return ends the function immediately

    def check_age(age):
    if age < 0:
        return "That is not a valid age."
    if age >= 18:
        return "Adult"
    return "Minor"

print(check_age(20))    # Adult
print(check_age(-5))    # That is not a valid age.

    Nothing after a return that runs will execute, which makes it useful for handling bad input first and getting out early.

    Local vs. global scope

    A variable created inside a function only exists inside that function — its local scope. It disappears the moment the function finishes. 

    def set_score():
    score = 100
    print(score)

set_score()
print(score)   # NameError: score is not defined

    A variable created outside any function lives in the global scope and can be read from inside a function: 

    message = "Hello"

def show_message():
    print(message)   # reading a global works fine

show_message()
    Careful — scope leakage

    A function cannot change a global variable just by assigning to a name with the same one inside it — that creates a new local variable instead, and the global is left untouched. Return the new value and reassign it outside the function rather than fighting scope rules.

    Worked example — refactoring into functions

    This chapter's project turns a quiz into a set of small functions, each doing exactly one job. 

    # Quiz Game

def ask_question(question, correct_answer):
    given = input(question + " ")
    return given.strip().lower() == correct_answer.lower()


def report(score, total):
    print(f"\nYou scored {score} out of {total}.")
    if score == total:
        print("Perfect.")
    elif score >= total / 2:
        print("A decent effort.")
    else:
        print("Worth another go.")


questions = [
    {"q": "What symbol starts a comment in Python?", "a": "#"},
    {"q": "What is 7 * 6?", "a": "42"}
]

score = 0

for item in questions:
    if ask_question(item["q"], item["a"]):
        print("Correct.")
        score += 1
    else:
        print(f"No — the answer was {item['a']}.")

report(score, len(questions))
    Output 
    What symbol starts a comment in Python? #
Correct.
What is 7 * 6? 42
Correct.

You scored 2 out of 2.
Perfect.

    ask_question returns a boolean rather than printing anything, so the loop that calls it decides what to do with the result — exactly the return-over-print habit this chapter argued for.

    Small exercise

    What does this print, and why is it not 8?

    def double(number):
    number * 2

print(double(4))

    It prints None. The function calculates the double and throws it away — there is no return.
