    What programming actually is

    A computer is astonishingly fast and completely unimaginative. It will do exactly what you tell it, in exactly the order you tell it, several billion times a second — and it will never once work out what you meant. Programming is the craft of writing instructions precise enough for something that literal.

    That is the whole job. Not memorising syntax, not knowing every function by heart. Taking a task you understand, breaking it into steps small enough that nothing is left to interpretation, and writing those steps down in a language the machine can read. This course uses Python, because it reads closer to English than most languages and gets out of your way while you are learning the ideas underneath.

    Note

    People often compare programming to giving directions. The better comparison is giving directions to someone who has never been outside, cannot see, and will walk into a wall rather than assume you meant "turn before the wall".

    Setting up your environment

    Before you can write a program, you need Python itself installed, and somewhere to write your code. The steps below get you there without needing anything else — the video above covers the same ground if you would rather be talked through it, but it is optional. Follow whichever one matches your computer.

    Installing Python on Windows

    1. Go to python.org/downloads and click the yellow "Download Python" button — it detects Windows automatically.
    2. Run the installer. On the very first screen, before clicking Install, tick "Add python.exe to PATH" at the bottom of the window.
    3. Click "Install Now" and let it finish.
    Careful

    That PATH checkbox is the single most common reason a beginner's install "doesn't work." If you miss it, Windows will not know what to do when you type python in a terminal. If that happens, re-run the installer and choose "Modify" — the checkbox is there too.

    Installing Python on macOS

    1. Go to python.org/downloads and download the macOS installer (a .pkg file).
    2. Open it and click through the installer with the defaults.
    Tip

    On macOS the command is usually python3, not python — the older name is reserved by a different, ancient version of Python that ships with the system. If python does not work below, try python3 instead.

    Getting an editor: VS Code

    A code editor is where you actually type your programs. This course uses VS Code — free, and the most widely used editor for Python beginners.

    1. Download it from code.visualstudio.com and install it.
    2. Open VS Code, click the Extensions icon on the left sidebar (four squares), search for "Python" (the official one, published by Microsoft), and click Install.

    Checking it worked

    Open a terminal — Terminal in VS Code's menu (View → Terminal), or your system's own terminal app — and type: 

    python --version
    Output 
    Python 3.12.4

    Any version number appearing means the install worked and PATH is set up correctly. If instead you see something like 'python' is not recognized or command not found, the install did not finish correctly — go back and check the PATH checkbox (Windows) or try python3 --version (macOS).

    Running your first file

    Create a new file in VS Code, save it as hello.py, and type one line into it: 

    print("Hello, world!")

    Then, in the terminal, make sure you are in the same folder as the file and run: 

    python hello.py
    Output 
    Hello, world!
    Tip

    Save your files with a .py ending, for example hello.py. That extension is what tells your editor, and Python itself, that the file contains Python code.

    If that printed Hello, world!, everything is working — do the rest of this course from that same setup.

    Execution flow: how a program actually runs

    When you run a Python file, Python reads it from the very top line and works downward, one instruction at a time, in order. This sounds obvious written down, but it is the single most important fact to hold in your head for the rest of this course. 

    print("First")
print("Second")
print("Third")
    Output 
    First
Second
Third

    Three lines, run top to bottom, in exactly that order — never bottom to top, never out of sequence. When a program misbehaves later in this course, tracing which line ran when will find the fault more often than staring at the whole file will.

    print(): showing something on screen

    print() is a built-in function — a piece of work Python already knows how to do. This one displays whatever you give it. 

    print("Hello, world!")
    Output 
    Hello, world!

    Take that line apart, because every piece matters:

    • print is the function's name.
    • The brackets ( ) are how you call a function — they hold whatever you are handing it.
    • The quotation marks mark the start and end of a piece of text. Without them, Python would think Hello was the name of something you had already defined, and it isn't.

    You can print more than one thing at once by separating them with commas. Before running it, guess what shows up between "is" and "42":

    Predict the output 
    print("The answer is", 42)
    The answer is 42

    Python adds a single space between each comma-separated item automatically — you never have to type it yourself.

    input(): asking the person using your program

    A program that only ever works with text you typed into the file is not very useful. input() pauses the program, waits for the person to type something and press Enter, and hands back whatever they typed. 

    name = input("What is your name? ")
print("Hello,", name)
    Output (with "Alex" typed) 
    What is your name? Alex
Hello, Alex

    The text inside the brackets is the prompt — it is shown before the program waits. You will meet input() again in almost every chapter from here on, because it is how a program stops only doing what you already knew and starts reacting to something new.

    Careful

    Whatever someone types into input() comes back as text, even if they type a number. You will learn how to convert that text into an actual number in the next chapter — for now, just notice that input() always waits, and always hands back text.

    Comments: notes to humans

    A line starting with # is a comment. Python ignores it completely when the program runs — it exists purely for whoever reads the file afterwards, which is usually you, in three weeks, having forgotten why you did something. 

    # Greet the person using the program
print("Hello, world!")   # this part runs; the note after the hash does not
    Tip

    Write comments about why, not what. # print the total tells a reader nothing they could not already see. # totals must exclude tax here tells them something real.

    Reading errors without panicking

    You are about to see a great many error messages over this course, starting today. That is not a sign anything has gone wrong with you — it is the normal texture of the work. 

    print("Hello, world!"
    Output 
      File "hello.py", line 1
    print("Hello, world!"
         ^
SyntaxError: '(' was never closed

    Read the last line first — it names the exact fault. Then the line number tells you where. Every piece of that message is a gift, not a scolding, and this specific error means one thing only: a bracket that opened was never closed.

    Small exercise

    Before continuing, run this in your editor and read the actual error Python gives you: 

    Print("Hello")

    It fails because Print is capitalised and Python's real function is lowercase — print. Spelling and case always matter.

    Putting it together

    Everything in this chapter is small on its own, but together it is enough to write a real, working program: 

    # Ask for a name and greet them
name = input("What is your name? ")

# Show the greeting
print("Welcome to Pung Academy,", name)
    Output (with "Alex" typed) 
    What is your name? Alex
Welcome to Pung Academy, Alex

    Four lines, read top to bottom, using a function that shows things, a function that asks for things, and two comments explaining why. Everything else in this course is this same idea, with more tools added one chapter at a time.
