    Learning material

    Modelling a real thing

    So far, related information has lived in separate variables or a dictionary — a student's name here, their grade there. A class bundles data and the actions that belong to it into one definition, and lets you create as many independent copies, or objects, as you need.

    Defining a class

    class Dog:
    def __init__(self, name):
        self.name = name

    def bark(self):
        print(f"{self.name} says Woof!")

    Take it apart:

    • class Dog: — starts the definition. By convention, class names start with a capital letter.
    • __init__ — a special method that runs automatically the moment a new Dog is created. It sets up the object's starting state.
    • self — refers to this particular object. Every method needs it as its first parameter.
    • self.name = name — stores the value as an attribute, so every method on this object can read it later.

    Creating and using objects

    rex = Dog("Rex")
milo = Dog("Milo")

rex.bark()    # Rex says Woof!
milo.bark()   # Milo says Woof!

    rex and milo are two separate instances of the same class, each with its own independent name. Calling rex.bark() automatically passes rex as self — that is how the method knows to print "Rex" and not "Milo".

    Methods with more than self

    A method can take extra parameters just like a normal function:

    class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

    def withdraw(self, amount):
        if amount > self.balance:
            print("Insufficient funds.")
        else:
            self.balance -= amount


account = BankAccount("Alex")
account.deposit(100)
account.withdraw(30)
print(account.balance)   # 70

    Class attributes vs. instance attributes

    An attribute set inside __init__ with self. belongs to one specific object. An attribute written directly under the class, outside any method, is shared by every object of that class. 

    class Dog:
    species = "Canis familiaris"   # class attribute -- shared by every Dog

    def __init__(self, name):
        self.name = name           # instance attribute -- unique per Dog

rex = Dog("Rex")
milo = Dog("Milo")

print(rex.species, milo.species)   # both print the same shared value
print(rex.name, milo.name)         # each prints its own
    Careful

    Assigning to self.species = "..." on one instance creates a new instance attribute that only shadows the class attribute for that one object — it does not change the shared value for every Dog.

    Inheritance

    A class can be built on top of another one, inheriting its attributes and methods and adding or overriding what it needs. 

    class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        print(f"{self.name} makes a sound.")


class Cat(Animal):
    def speak(self):
        print(f"{self.name} says Meow!")


generic = Animal("Some animal")
whiskers = Cat("Whiskers")

generic.speak()    # Some animal makes a sound.
whiskers.speak()   # Whiskers says Meow!

    Cat(Animal) means "a Cat is an Animal, plus whatever is different." Because Cat defines its own speak, calling it on a Cat uses that version rather than the parent's — Python looks for the method on the object's own class first, and only checks the parent if it does not find one there.

    Encapsulation

    Encapsulation means keeping an object's internal details bundled inside it, and interacting with the object through its methods rather than reaching directly into its attributes from outside. Python does not enforce this strictly, but a leading underscore is the conventional signal that an attribute is meant to stay internal: 

    class BankAccount:
    def __init__(self, balance):
        self._balance = balance   # the underscore says "internal - use the methods"

    def get_balance(self):
        return self._balance

    Worked example — the BankAccount class

    # BankAccount

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount
        print(f"Deposited {amount}. New balance: {self.balance}")

    def withdraw(self, amount):
        if amount > self.balance:
            print("Insufficient funds.")
        else:
            self.balance -= amount
            print(f"Withdrew {amount}. New balance: {self.balance}")


account = BankAccount("Alex", 50)
account.deposit(20)
account.withdraw(100)
account.withdraw(30)
    Output 
    Deposited 20. New balance: 70
Insufficient funds.
Withdrew 30. New balance: 40
    Small exercise

    Given the Cat(Animal) example above, if Cat did not define its own speak method, what would whiskers.speak() print? "Whiskers makes a sound." — with no override, Python falls back to the parent class's version.
