    What a computer actually is

    Strip away the screen, the apps and the icons, and a computer is a machine built from four parts working together. Every device you own — a laptop, a phone, a games console — is some arrangement of these same four things:

    • CPU (Central Processing Unit) — the part that actually does the work. It carries out instructions one at a time, extremely fast: modern CPUs run billions of instructions every second.
    • Memory (RAM) — a fast, temporary workspace. Whatever the CPU is working with right now lives here. It is wiped clean the moment the power goes off.
    • Storage — a hard drive or SSD. Slower than memory, but it keeps its contents with the power off, which is why your files are still there tomorrow.
    • Input and output — how the computer talks to the outside world. A keyboard and mouse are input; a screen and speakers are output.
    Note

    A useful way to hold these four in your head: storage is a filing cabinet, memory is the desk you are working at, and the CPU is you, doing the work. You can only act on what is on the desk, and the desk is cleared at the end of the day.

    Every single thing your computer ever does — playing a video, opening this page, running a program you write in a few chapters from now — is these four parts moving data between each other, at a scale too fast to see.

    The one thing a CPU understands

    A CPU cannot read English, and it cannot read Python. The only thing it can carry out is machine code — long streams of binary, just 0s and 1s, wired directly into how that specific processor was built. 

    01001000 01100101 01101100 01101100 01101111

    Nobody writes programs like that by hand any more. It is unreadable, painfully slow to produce, and tied to one exact type of processor. Everything since has been an effort to let humans write something closer to how they actually think, and have the machine translate it down to this.

    What a programming language is

    A programming language is a fixed, precise set of words and symbols for describing instructions — precise enough that a translator program can turn it into machine code without ever having to guess what you meant. That is the entire purpose of a language like Python: it lets you write print("Hello") instead of the binary above, while something else handles the translation.

    The text you type into a file — readable, with words like if and print — is called source code. It means nothing to the CPU on its own. Something has to turn it into machine code first, and there are two different ways that happens.

    Compilers and interpreters

    Both take source code and produce something the CPU can run — they just do it at a different time, and in a different way.

    • A compiler reads the entire program up front and translates all of it into machine code in one pass, before the program ever runs. The result is a standalone file the CPU can execute directly, every time, with no translation step left to do. C and C++ work this way.
    • An interpreter reads and translates the program one instruction at a time, running each one immediately before moving to the next. There is no separate finished file — the interpreter has to be present every time the program runs. Python works this way.
    Tip

    This is why the video in Chapter 2 has you install Python itself before you can run anything: the file you write is only source code. Python, the interpreter, is the program that actually reads it and carries it out, line by line.

    Why this course uses Python

    Every language makes the same trade-off differently: how close to English should it read, versus how much control and speed does it give up to get there. Python leans hard toward readability. 

    name = input("What is your name? ")
print("Hello,", name)

    Read that and you can already guess what it does, even before Chapter 2 explains input() and print() properly. That readability is not an accident — it is Python's entire design philosophy, and it is why it is usually recommended as a first language: the ideas underneath programming are hard enough to learn without also fighting unfamiliar punctuation.

    Careful

    Readable does not mean simple. Python runs the software behind major websites, scientific research and machine learning systems. What you are about to learn is the same language used for all of that — you are just starting, deliberately, at the very beginning of it.

    Putting it together

    Hold onto this one chain of ideas, because the rest of the course builds directly on top of it: you write source code in a language like Python, an interpreter translates it into machine code the CPU can actually run, and the CPU, memory, storage, and input/output are the physical machine that carries it out. From the next chapter on, you will be the one writing that source code.
